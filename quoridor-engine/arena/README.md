# Арена

Сравнение движков: парные партии (один дебют, обмен цветов), Elo с доверительным интервалом, SPRT с
ранней остановкой, round-robin с рейтингом Bradley-Terry, параллельные партии через `worker_threads`,
лог каждой партии в JSONL.

Арена ничего не знает про Quoridor. Всё общение с игрой идёт через адаптер
(`src/match.js` вызывает только эти восемь функций):

```
createInitialState()            cloneState(s)              currentPlayer(s)
winner(s) -> 0|1|null           positionKey(s) -> string   legalMoves(s) -> move[]
applyMove(s, m) -> {state}|{error}
makeBot(spec, name) -> { newGame(seed), think(state, playerIdx, limits) -> move }
```

Адаптеры: `adapters/quoridor.js` (боевой) и `adapters/toy.js` (Nim, самопроверка самой арены).

## Запуск

```bash
# матч с SPRT: принять новую версию, только если она лучше v0 хотя бы на 5 Elo
node src/cli.js match --adapter ./adapters/quoridor.js --bots ./bots.json \
     --a v0-hard --b v0-medium --games 2000 --movetime 100 --sprt 0,5 --out results/hard-vs-medium.jsonl

# все против всех + рейтинг (якорь: v0-medium = 0)
node src/cli.js roundrobin --adapter ./adapters/quoridor.js --bots ./bots.json \
     --games 200 --movetime 100 --anchor v0-medium

# самопроверка арены на игре-заглушке
node src/cli.js match --adapter ./adapters/toy.js --bots ./bots.toy.json \
     --a smart --b random --games 200 --threads 2 --sprt 0,20 --out results/selftest.jsonl
```

Флаги: `--threads N` (по умолчанию ядра-1), `--seed`, `--movetime ms | --depth N | --nodes N`,
`--opening-plies N` (по умолчанию 4 случайных полухода), `--max-plies 300`, `--repetition N`,
`--no-moves`, `--out file.jsonl`.

`--repetition N` — сколько встреч одной позиции считать петлёй. **`N=0` отключает правило** (партия
идёт до `--max-plies`): это режим, чтобы отличить «бот застрял в цикле» от «бот долго меедлит».
`N=1` — **не** способ отключить, а наоборот срабатывание на первом же повторе: партия кончается
почти сразу, и в результат идёт мусор.

## Петли: не ничья, а баг

Ничья по повтору — не правило Quoridor, а чужеродный Draw, который арбитр ввёл, чтобы матч
заканчивался. У `v0-hard` против `v0-medium` это была примерно половина партий, а против самого себя
— 48.5%; у `v1-hard` против себя — 0%. Это признак того, что движок не умеет выбираться из цикла,
поэтому доля повторов измеряется и показывается отдельно от score:

```
loops: 23/40 (57.5%)  loop starts at ply ~30  median loop 8 plies   <-- HIGH: score is dominated by stalls
```

`loop starts at ply ~30` — ход, с которого начался **текущий цикл**, то есть последнее предыдущее
появление позиции. Не то, на котором арбитр сдался. Разница принципиальна: «зациклился с 4-го хода» и
«дошёл до 200-го и застрял» чинятся совершенно разными способами. Пока доля повторов выше ~20%,
любой SPRT измеряет в основном скорость застревания, а не силу, и тюнинг весов по такому score
оптимизирует баг.

Длина партий показывается рядом, потому что score её не отражает:

```
plies: mean 72.0  median 72  min 25  max 107
```

Растущее среднее при неизменном score — верный признак, что движок стал меедлить; падающее — что
он выигрывает быстрее, иногда за счёт застревания соперника.

Похожая оговорка про слабость защиты от петель: движок читает `history[].prevPos`, но редуктор
(`rules/quoridor-rules.js`) кладёт в историю только `move`, поэтому `prevPos` нет **никогда** и
работает фолбэк — штраф за возврат в клетку *назначения* прошлого хода, а не *отправления*. Это
дефект не арены, а серверного `ai-core.js` (там тот же фолбэк), то есть на сайте он выражен так же.
Для сравнения версий это константа; для игры чинить надо в `gameReducer`.

Из корня `quoridor-engine` то же самое доступно как `npm run match`, `npm run rr`, `npm run arena:selftest`.

## Что уже сделано (и почему так)

Первой версии арены не существовало — был набор заготовок с пометками `ADAPT`. Три вещи в нём были
не просто недоделаны, а молча давали неверные числа:

1. **`GOAL_ROW = [8, 0]`** — это стартовые ряды, а не целевые. Любая позиция выглядела завершённой, и
   каждая партия заканчивалась на нулевом ходу. Теперь строка цели берётся из правил (`Rules.GOAL_ROW`).
2. **`gameReducer(clone, move, s.currentPlayer)`** — а `gameReducer(state, action)` читает игрока из
   самого `action` и бросает `Not your turn`, если его там нет. Третий аргумент игнорировался, поэтому
   отклонялся **каждый** ход. Теперь `playerIdx` передаётся внутри action.
3. **Общая TT между ботами** — старый адаптер делал копию модуля `ai-core` через `delete require.cache`,
   чтобы у каждого бота была своя таблица. Это глобальный побочный эффект, и он ломается, как только
   адаптеров в процессе больше одного. Теперь на каждую партию создаётся новый экземпляр движка.

Всё это закрыто тестами в `../tests/arena-adapter.test.js` — не потому что «хорошо бы», а потому что
все три бага давали результат, а не ошибку.

## Уровни сложности v1

Четыре игровых уровня, различаются **только глубиной поиска**:

| бот | `maxDepth` | измеренный Elo относительно себя |
|---|---|---|
| `v1-easy` | 2 | −28 |
| `v1-medium` | 3 | −5 |
| `v1-hard` | 4 | −4 |
| `v1-expert` | 5 | +37 |

Порядок монотонный, инверсий нет (круговой турнир, 200 партий на пару, 10000 узлов).
Разница между соседними уровнями маленькая: `v1-medium` против `v1-easy` — 25.1 Elo [3.5, 46.8]
на 1000 партиях, LOS 98.9%. Игрок может не почувствовать разницы между уровнями 1 и 2.

**Почему `difficulty: "hard"` у всех четырёх.** Метка `difficulty` в движке управляет только двумя
вещами: глубиной по умолчанию (`DEPTH_BY_DIFFICULTY`) и случайными ходами. Случайный ход
срабатывает исключительно при `difficulty === "easy"` и берётся ДО применения запрета на недавние
клетки, то есть возвращает петли. Поэтому уровни заданы меткой `"hard"` (единственная, которая не
включает случайные ходы) с явным `maxDepth`. Случайных ходов на уровнях нет, петель нет: 0/1000.

Глубина выше 5 не используется осознанно: depth 9 против depth 5 — Elo −76.5 [−143.0, −15.1],
LOS 0.8% на 100000 узлов. Углубление здесь вредит, поэтому «эксперта» выше `v1-expert` не существует.

## Правила методики

- `--games` чётное: партии 2k и 2k+1 начинаются с одной позиции, цвета меняются.
- Обоим ботам — **одинаковый лимит** (время или узлы). При матчах по времени не нагружайте машину.
- Изменение принимается только по SPRT. Погрешность Elo ≈ ±680/√N (95%).
- В пуле держите якоря: старые версии плюс `v0-random`.
- **Ничья по повтору — это баг, а не результат.** Из-за слабой антицикловой эвристики v0 часто сходит
  на повтор: в матче `v0-hard` против `v0-medium` около 40-58% партий заканчиваются повтором. Для
  сравнения версий это шум; при разборе смотрите на `reason` и строку `loops:` в отчёте, а не только
  на score. Ничья по правилам Quoridor невозможна — партия заканчивается, когда кто-то дошёл до
  чужого ряда.
- Сид партии выводится из параметров матча (`seed` + номер партии в паре), а не из порядка постановки
  в пул: иначе один и тот же матч с `--threads 2` и `--threads 4` давал бы разные результаты.

## Формат лога (одна строка = одна партия)

`{a, b, gameId, openingId, aFirst, aScore, plies, openingLen, reason, timeMs:[a,b], moves:[...]}`

`reason`: `win | repetition | maxplies | illegal:.. | crash:.. | no-move`.
Нелегальный ход или падение = поражение ходившего, причина попадает в лог целиком.

Для `reason: repetition` добавляются:
- `loopStartPly` — ход, с которого начался **текущий** цикл, то есть последнее предыдущее появление
  этой позиции. Именно это и есть начало петли;
- `loopLength` — `plies - loopStartPly`, длина текущего цикла в полуходах;
- `positionsSeen` — сколько разных позиций встретилось за партию;
- `loopFirstSeenPly` — когда позиция встречалась **впервые** за партию. Обычно он меньше
  `loopStartPly`, и разница показывает, сколько раз позиция уже была в игре до текущего захода.

Осторожно: раньше `loopStartPly` считался по ПЕРВОМУ появлению позиции, а не по последнему
повторению, и метрика врала примерно вдвое (показывала 16 при настоящей длине цикла 8). Смысл
полей прежний, но теперь они отвечают на свой вопрос.

ВНИМАНИЕ: `--out` открывает файл на **добавление** (`runner.js`), повторный запуск дописывает в
конец, а не перезаписывает. Для чистого замера указывайте новое имя файла.
