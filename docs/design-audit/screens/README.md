# Скриншоты — НЕ СОБРАНЫ

Эта папка пуста. Ни один скриншот приложения не был снят.

## Причина

По решению заказчика аудит выполняется **«только код, без запуска»**: приложение (локальный Docker / прод `playquor.org`) не поднималось, Playwright не использовался. Скриншоты требуют запущенного UI и, для большинства значимых экранов, ещё и учётных данных, поэтому в рамках текущего аудита они не собирались.

## Что именно не собрано

- Full-page скриншоты маршрутов и состояний (пары `1440×900` и `390×844`, языки **EN** и **RU**), имена по шаблону `route-state-width.png` (из ТЗ аудита).
- Состояния: главное меню, режим/настройки, онлайн-поиск, приватная комната, партия с ботом, партия онлайн, PvP (локально), экран профиля (Rating/History/Friends/Settings), лидерборд, реплей, вход/регистрация/сброс пароля, rules/faq/terms/privacy, отчёт и «мои отчёты», все admin-страницы.
- Визуальные состояния «загрузка / пусто / ошибка / гость / залогинен / админ» для этих экранов.
- Мобильная вёрстка и реальные computed-стили (см. `../tokens.md` §6).

## Как дособрать (когда будет разрешён запуск)

1. Поднять локальный стек: `docker compose -f docker-compose.dev.yml up -d --build` (чистая БД, тестовые данные; см. `../stack.md` §2, §10).
2. Создать пользователей: обычного и админа (`ADMIN_EMAILS`/роль в `.env`, см. `../stack.md`), а также несколько партий/друзей для непустых состояний профиля и лидерборда.
3. Playwright (Chromium) в двух viewport: `1440×900` и `390×844`; для каждого маршрута прогнать оба языка (`localStorage['quoridor-lang'] = 'en' | 'ru'`).
4. Зафиксировать состояния переключением классов/скринов: `body` (тема — фактически только dark), `.screen.active` для `gameScreen`/`profileScreen`; для модалок и панелей — соответствующие `.active`/`.open` классы (см. `../components.md`).
5. Именовать по шаблону `route-state-width.png`, например `home-default-1440.png`, `profile-history-ru-390.png`, `admin-dashboard-1440.png`.
6. Для каждого снимка указать: маршрут, состояние, язык, viewport, роль (гость/игрок/админ).

## Ограничения, которые надо учесть при досборе

- Прод использовать только с явного разрешения; для аудита предпочтителен локальный стек.
- Онлайн-состояния (поиск, живая партия, presence) нестабильны — снимать детерминированно или помечать как не детерминированные.
- Не все состояния достижимы без реальных данных (непустые friends/notifications/history/liveGames).
