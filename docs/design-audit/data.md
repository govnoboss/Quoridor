## 1. Ранг пользователя (в т.ч. вне топ-100) — **ЧАСТИЧНО**

- В модели `User` **нет поля `rank`** (см. `src/models/User.js`). Ранг нигде не вычисляется и не хранится.
- `GET /api/leaderboard?limit=N` возвращает массив пользователей, отсортированных по `rating` (только не-админы), `limit` ≤ 100. **Номер ранга в ответе отсутствует** — клиент сам рисует `i+1`:
  - таблица лидерборда (`leaderboard.html:281` → `(i + 1)`);
  - боковой блок в меню (`ui.js:3431` → `<span class="rank">${i + 1}</span>`).
- Итог: ранг виден **только для игроков из топ-100**; для пользователя вне топ-100 ранга нет ни в API, ни в UI. Профиль ранг не показывает.
- Чтобы добавить: нужен серверный расчёт позиции (например, count по `rating > X`) или поле в ответе `GET /api/profiles/:username`.

## 2. История рейтинга за N партий — **ЧАСТИЧНО**

- `GET /api/profiles/:username/rating-history` возвращает **всю** историю ranked-игр:
  ```json
  [{"date":"2026-01-05T…","ratingAfter":1212},{"date":"2026-01-07T…","ratingAfter":1205}]
  ```
- Рейтинг **реконструируется** на сервере от стартовых `1200`, складывая `playerWhite/Black.ratingChange` по дате.
- Параметра «за N партий» нет — клиент получает всё и рисует график (Chart.js) целиком, затем сворачивает секцию. Ограничение/выбор N нужно добавлять.

## 3. Изменение рейтинга за 7 дней — **НЕТ**

- Отдельного эндпоинта нет. Ни `GET /api/user/history`, ни `GET /api/profiles/:username/rating-history` не отдают дельту за окно.
- В `rating-history` есть точки `{date, ratingAfter}` — из них 7-дневную дельту можно вычислить **на клиенте**, но такой логики в коде нет.
- В профиле показываются только изменения рейтинга **по каждой партии** (`playerWhite/Black.ratingChange`), не агрегат за период.

## 4. % побед в таблице — **ЧАСТИЧНО**

- Профиль: карточки `.pp-stats-overview` — Games, W/L, **Winrate** (`#ppWinrate`), Rating. Winrate берётся из `stats.wins`/`stats.totalGames`.
- `GET /api/profiles/:username` отдаёт `stats: {totalGames, wins, losses, playTimeSeconds}` → winrate вычисляется на клиенте.
- Таблица лидерборда (`/leaderboard`) содержит колонки: **Rank, Name, Rating, Games** — **процента побед нет**. `GET /api/leaderboard` возвращает `stats.totalGames`, но не `wins`, поэтому winrate там даже в теории не посчитать без изменения ответа.
- Итог: процент побед есть в профиле, но не в таблице.

## 5. Ссылка на реплей в строке истории — **ЧАСТИЧНО**

- В таблице истории профиля колонок 5: Date, Opponent, Result, Rating(Δ), Moves (`game.turns`). Отдельной колонки/ссылки «Replay» **нет**.
- **Вся строка** кликабельна: `ui.js:2805-2806` → `row.onclick = () => UI.openReplayModal(game._id)`, что ведёт на `/replay/:id`. Внутри строки есть вложенная ссылка на профиль соперника (`event.stopPropagation()`).
- То есть функция есть, но **не визуализирована** (нет иконки/подписи «смотреть реплей») — UX-проблема обнаруживаемости. Данные реплея доступны: `GameResult.history` + `GET /api/games/:id`.

## 6. Список идущих партий — **ЕСТЬ**

- Реализовано через Socket.IO, а не REST. Сервер рассылает `onlineStats` с полем `liveGames`:
  ```json
  { "online": 22, "playing": 5,
    "humans": [{"name":"alice","inQueue":true}], "bots": [{"name":"Bot-7","inQueue":false}],
    "liveGames": [{"players":[{"name":"alice"},{"name":"bob"}]}] }
  ```
- Клиент: `net.js` (`socket.on('onlineStats')`) → `UI.updateOnlineStats(data)` → `UI.renderPresenceLists(data)` → `#liveGamesList` (`games.map(g => g.players[0].name + ' vs ' + g.players[1].name)`).
- REST-эквивалента нет (только сделанный подписка на сокет-событие).

## 7. Список онлайн-игроков — **ЕСТЬ**

- Тот же `onlineStats`: поля `humans` (с флагом `inQueue`) и `bots`. Счётчики `online`/`playing` идут в `#statsOnlineCount`/`#statsPlayingCount`.
- Клиент рисует `#onlinePlayersList` (`.presence-row`), клик по нику → `UI.showProfilePage(name)`. Пустое состояние — `presence_empty`.
- Ограничение: у элемента только `name` (нет аватара/рейтинга/статуса). REST-эндпоинта «онлайн-список» нет.

## 8. Смысл «Local Game» — **ЧАСТИЧНО / неоднозначно**

- Кнопка «**Локальная игра**» (`menu_local_game`) вызывает `UI.onPlayLocalClick()`, который просто открывает `panelMode` — выбор режима **PvP (два игрока за одним устройством) ИЛИ игра с ботом** (`ui.js`):
  ```js
  onPlayLocalClick() { trackEvent('play-local-click'); this.showDynamicPanel('panelMode'); }
  ```
- Отдельного понятия «локальная партия» (локальный матч двух живых игроков) как сущности/режима нет: это зонтик над PvP и ботами. Ярлык «Локальная игра» вводит в заблуждение (внутри есть и бот-игры).
- `Game.startPvP()` запускает партию двух игроков на одном устройстве; отдельный режим `gameMode = 'local'` используется в аналитике (`game-started` `{mode:'local'}`).

## 9. Обучение — **ЧАСТИЧНО**

- Есть текстовые материалы: панель «Как играть» (`#panelHowToPlay`, 4 секции: цель/ходы/стены/совет) и отдельная страница `/rules` (полный текст с иллюстрациями-текстом, EN+RU).
- **Интерактивного обучения/туториала (пошагового) нет.** Кнопки его запуска в UI отсутствуют.
- На главной есть демо-доска (`#demoBoard`) — декоративная, не обучающая.

## 10. Друзья и приглашение по ссылке — **ЕСТЬ**

- **Друзья**: полный цикл — `POST /api/friends/request`, `…/accept`, `…/decline`, `DELETE /api/friends/remove/:userId`, `GET /api/friends/list` (`{friends, incoming, outgoing}`). UI: таб Friends в профиле, добавление по нику (поиск через `GET /api/profiles/:username`, затем `UI.addFriend(id)`). Онлайн-статус друзей — через сокет-события `friendOnline`/`friendOffline`.
- **Приглашение в игру другу**: Socket.IO `inviteToGame` (→ у друга уведомление `game_invite`) и `acceptGameInvite`.
- **Приглашение по ссылке**: «Играть с другом» создаёт приватную комнату (`createRoom`), UI показывает код (`#roomCodeValue`) и ссылку (`#roomLinkDisplay`, формат `/lobby/<CODE>`, маршрут `GET /lobby/:lobbyCode`). Есть копирование (`UI.copyRoomCode`/`UI.copyRoomLink`).
- Итог: и друзья, и приглашение (и по ссылке-комнате, и другу в игру) реализованы.

## Дополнительно замечено (влияет на доступность данных)

- `GET /api/leaderboard` не отдаёт `wins`/`losses` → winrate и «% побед» в таблице невозможно без изменения ответа.
- `GET /api/user/history` и `GET /api/profiles/:username/games` возвращают `{games,total,page,limit}` — пагинация есть, но нет агрегатов (winrate за период, дельта рейтинга за период).
- `onlineStats` отдаёт минимум полей (только `name`/`inQueue`) — для «онлайн-списка» с аватарами/рейтингом данных недостаточно.
- Ранг нигде не персистится; всё, что похоже на «ранг», — это позиция в конкретной выдаче лидерборда.
