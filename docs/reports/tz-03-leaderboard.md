## Обстоятельства проверки

- Браузер доступен только с фиксированным вьюпортом **1296×886** (изменить размер окна нельзя: `window.resizeTo` не работает). Замеры сделаны на этом вьюпорте; координаты, зависящие от ширины (x=360 → «контейнер по центру»), проверяются по факту центровки.
- `design-reference/` в репо отсутствует — сверка с макетом-эталоном (`png/Leaderboard.png`) невозможна; всё сделано по точным значениям ТЗ.

- Скриншоты не получены: браузерная вкладка не видна на рабочем столе (`browser.screenshot` требует видимую вкладку). Вместо них — полные покомпонентные замеры (п. 2) и DOM-снапшоты — повторяет экономный путь из раздела 0 ТЗ с той же снимаемой информацией.
- Коммиты: `9ef1faf` (реализация ТЗ), `49abfe4` (токены/шеврон), `fe50794` (package-lock), `5df7ee7` (масштаб по высоте), `ba6ddff` (единая шапка на статических страницах).

## 3. Что из API не получилось / ограничения

- **`delta7` и `winrate`**: реализованы полностью (`GET /api/leaderboard`, сортировки rating/winrate/week, `delta7` — одна агрегация по GameResult за 7 дней, MIN_GAMES_WINRATE=10, `GET /api/leaderboard/me`). Отключать ничего не пришлось — вкладка «This week» работает.
- **Кэш `delta7` (Redis)**: Redis локально нет — тесты идут через in-memory fallback (`sessionRedisClient` может отсутствовать), в проде кэш 5 мин в Redis с откатом на память. Разница покрыта тестами.
- **«You»-строка**: показывается только залогиненному (мок-cookie проверен: ранг — позиция в текущей сортировке, sticky).
- **`limit=500` → обрезка до 100**, email в ответах отсутствует — проверено тестами.
- Тесты: 27 passed, 5 skipped (skip — без `sharp` на Node 18.12.1, младше требуемых 20.9; на проде avatar-генерация работает, `sharp` подключается лениво).

## 4. Что не получилось

1. **Скриншоты** (обрезанный подиум и шапка таблицы) — вкладка браузера не видна на рабочем столе; вместо них полные геометрические замеры выше.
2. **Точная сверка с `png/Leaderboard.png`** — `design-reference/` нет в репо.
3. **Физическое изменение вьюпорта** (1440×900 / 1920×1080 / 390×844) — окно браузера не ресайзится.
4. **ESLint 10** не запускается на Node 18.12.1 (`util.styleText`); Jest требует polyfill через `NODE_OPTIONS`.
5. Локальная БД (Mongo/Redis) — проверка через mock-сервер, прод-поведение покрыто юнит-тестами с моками.

## 5. Найденные, но не исправленные проблемы (внеэтапные)

1. **Email в других публичных ответах**: `onlineStats`, история партий, профиль соперника — могут отдавать email; ТЗ 4.4 требует нигде не показывать. Отдельная задача.
2. **Запрет `@` в username** при регистрации/Google-входе отсутствует — источник проблемы №12; лечится валидацией при создании аккаунта.
3. **Файлы-фавиконы**: `frontend/favicon*.{png,ico}` и `add_favicon.sh` остаются untracked — страницы на них не ссылаются (прецедент `5b182a5`).
4. Компакт-тиры по высоте (≤960/≤820 px) — отступление от ТЗ, задокументировано в п. 1 (дефект 9); на мониторах 1080p подиум+таблица выше сгиба лежат плотнее, чем просил макет.

## Отступления (производное)

1. **Медаль вынесена из потока** (`position:absolute; top:8px; left:50%`), контент прижат к низу (`justify-content:flex-end`). Причина: при медали в потоке (28px) и `gap:6px`/`padding:16px` арифметика не сходится с жёсткими высотами 176 (минимум ~185px контента) — карточки переливались бы. В эталоне медаль визуально сидит у верхней кромки — совпадает. Зазор медаль→аватар: 16.2 / 3.2 / 3.2 px.
2. **`line-height:1.1`** у ник/рейтинг/games подиума — чтобы фикс. высоты 176/216 не переполнялись.
3. **Компактный тир 2 (≤960 по высоте) держит те же 176/216**, `margin-top:32px` (32−16=16 — нижняя граница зазора вкладка→корона); тир 3 (≤820) — `height:auto`, `min-height` 124/144. Скриншот подиума для сравнения с `top3-ideas.png` снять нечем — вкладка браузера не видна на рабочем столе; все контрольные значения подтверждены замерами.
4. На вьюпорте 1296×886 в первый экран попадает ~6 строк таблицы (было 8 до ТЗ 3a — карточки/отступ по ТЗ выше прежних компактных).
