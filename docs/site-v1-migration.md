# Задача: перевести сайт Quoridor на движок v1

Самодостаточный бриф. Тот, кто его выполняет, не обязан знать историю предыдущих
сессий. Все утверждения ниже проверяемы, у каждого есть команда проверки.

Работай в корне репозитория. Перед правками прочитай перечисленные файлы и не
начинай генерацию кода, пока не убедишься, что понимаешь структуру.

## Что уже есть в репозитории

Канонические правила игры — `quoridor-engine/rules/`. Это **единственная**
реализация правил, дублировать её нельзя ни при каких обстоятельствах.

- `quoridor-engine/rules/quoridor-rules.js` — сами правила, UMD: в Node
  экспортируется в `exports`, в браузере пишет `this.Shared = {}` (строка 367).
- `quoridor-engine/rules/index.js` — Node-обвязка, использует `path` и
  `require('./quoridor-rules.js')`. В браузере не нужна.
- `quoridor-engine/rules/paths.js` — экспортирует `RULES_FILE` (путь к
  `quoridor-rules.js`).
- Сервер отдаёт этот же файл в браузер по маршруту `/shared.js`
  (`src/server.js:126`, а также статика на `1306`). Поэтому в браузере правила
  доступны как глобальная переменная `Shared`.

Движки:

- `quoridor-engine/engines/v0/index.js` — старая базовая реализация, эталон
  парности: `quoridor-engine/tests/engine-parity.test.js` сверяет её с
  `src/core/ai-core.js`. **Нельзя трогать v0** — это точка отсчёта для тестов.
- `quoridor-engine/engines/v1/index.js` — актуальный движок, который нужно
  внедрить. CommonJS, фабрика `createEngineV1(options)`, экспорт
  `{ createEngineV1, DEFAULT_WEIGHTS, DEPTH_BY_DIFFICULTY }` (строка 740).
  Зависимости (строки 51-52): `require('../../rules')` и
  `require('../../tools/rng')`. `quoridor-engine/tools/rng.js` — чистый JS без
  Node-API, пригоден для браузера. Из правил v1 использует ровно 6 членов:
  `checkWallPlacement`, `cloneState`, `getJumpTargets`, `GOAL`,
  `isValidWallPlacement`, `isWallBetween`.
- `quoridor-engine/engines/v2/index.js` — экспериментальный, в задачу не входит.

Арена для замеров:

- `quoridor-engine/arena/src/cli.js` — команды `match` и `roundrobin`.
- `quoridor-engine/arena/adapters/quoridor.js` — мост к правилам и движкам,
  показывает правильный вызов движка.
- `quoridor-engine/arena/bots.json` — конфиг ботов.
- Важно: `quoridor-engine/arena/src/worker.js:8` держит **отдельный** экземпляр
  движка на каждое кресло в самопое. Это не оптимизация, а требование
  корректности (см. раздел про транспозиционную таблицу).

Что сейчас играет на сайте и почему это надо заменить:

- `src/core/ai-core.js` — отдельный **старый** движок в виде UMD. Это **не**
  обёртка над v1, это самостоятельная реализация с другой оценкой. Обслуживает:
  серверные fallback-боты (`src/bots/BotManager.js`, `src/bots/defaultBots.js`),
  генератор задач (`src/puzzles/puzzleGenerator.js`), браузер
  (`frontend/index.html:739`), воркер (`frontend/js/ai-worker.js:5`), локальный
  режим и подсказки (`frontend/js/game.js`).
- `src/core/shared.js` — Node-алиас канонических правил:
  `module.exports = require('../../quoridor-engine/rules')`.

## Цель

Сайт должен использовать **настоящий v1** во всех путях: серверные
fallback-боты, генератор задач, браузерный бот и Web Worker. Четыре уровня
сложности должны соответствовать глубинам **2/3/4/5**. Случайных ходов быть не
должно.

Уровни в интерфейсе уже есть — `easy`, `medium`, `hard`, `impossible`
(`frontend/index.html`). Соответствие: easy=2, medium=3, hard=4, impossible=5.

## Обязательные технические условия

1. **Сборщика нет, и добавлять его не нужно.** Браузер грузит JS напрямую через
   `<script>` и `importScripts`. Значит v1 отдаётся в браузер самосборным
   UMD-бандлом, который сервер генерирует на лету: встроить исходники
   `tools/rng.js` и `engines/v1/index.js`, а `require('../../rules')` отдавать в
   глобальный `Shared`. Никакого дублирования правил. Маршрут `/js/ai-core.js`
   сейчас отдаётся статикой (`src/server.js:119-120`, `1307`) — сделать
   аналогичный маршрут для бандла v1. В `frontend/index.html` и
   `frontend/js/ai-worker.js` `/shared.js` грузится раньше движка — этот порядок
   сохранить.

2. **Один экземпляр движка на каждое кресло и на каждую партию.** `tt` — это
   `Map`, который переживает партию, а ключ транспозиционной таблицы **не
   содержит `botIdx`**. Если один объект обслуживает обе стороны или несколько
   партий, второй игрок читает записи первого и получает бессмысленные оценки.
   На сервере это `BOT_MAX_ACTIVE_GAMES` (по умолчанию 15) параллельных игр, в
   браузере воркер переиспользуется между играми на странице. На Node
   `require()` кэширует модуль и отдаёт тот же объект, поэтому «свежий» движок
   нельзя получить повторным `require` — нужна фабрика. У v1 она уже есть
   (`createEngineV1`), у сайта придётся добавить.

3. **Глубины передавать явно через `maxDepth`, а не через `difficulty`.**
   В v1 `DEPTH_BY_DIFFICULTY = { easy: 2, medium: 3, hard: 5, impossible: 20 }`
   (строка 67) — это старые значения, они не совпадают с выбранными 2/3/4/5.
   Плюс `impossible: 20` вредна: замеры показали, что глубина 9 хуже глубины 5.
   Случайность отключить: `easyRandomP: 0`.

4. **Правильный вызов движка** (см. `arena/adapters/quoridor.js:120-141`):

   ```js
   const engine = createEngineV1({ seed, timeMs, maxDepth, nodes, easyRandomP, weights });
   const res = engine.think(state, { difficulty, player: playerIdx, maxDepth, timeMs, nodes });
   const move = res.move;   // НЕ res сам и НЕ think(state, botIdx)
   ```

   Сигнатура v1 — `think(state, limits)` с `player` внутри limits, возвращает
   `{ move }`. Это отличается от сигнатуры старого сайтового движка
   `AICore.think(state, botIdx, difficulty)`.

5. **Действие для редьюсера всегда несёт игрока внутри:**
   `Rules.gameReducer(state, { type, r, c, isVertical, playerIdx })`. Третий
   аргумент игнорируется — исторически из-за этого арена отвергала все ходы.

## Что перенести из v1 дополнительно: антиповтор

В v1 антиповтор сделан окном последних клеток: `RECENT_WINDOW = 3` (строка 65).
Механизм принципиально неполон: запрет окна в 3 клетки не способен закрыть цикл
длиннее 4 ходов. Это измерено на сайте: боты ставили цикл **периода 6**, и 100%
партий заканчивались повтором:

```
P0: (6,7)->(6,8)->(7,8)->(8,8)->(8,7)->(7,7)->(6,7)
P1: (7,2)->(8,2)->(8,1)->(8,0)->(7,0)->(7,1)->(7,2)
```

Запрет по факту повтора ловит цикл любой длины. Перенеси его в v1:

- ключ позиции: очередь хода, обе пешки, остаток стен у обоих игроков, обе сетки
  стен;
- собирать множество позиций, уже встречавшихся в партии, переигрывая
  `state.history` через `gameReducer` (в истории лежат только
  `{playerIdx, move, timestamp}`, `prevPos` там нет никогда);
- в корне поиска отбрасывать ходы пешки, которые дают позицию из этого
  множества;
- ходы стеной в проверку не включать — ими повтор создать нельзя;
- если запрет закрыл **все** ходы, список оставлять как есть, иначе бот встанет.

## Точка отсчёта для проверки (обязательно воспроизвести)

Самопой v1-hard против себя в арене, 150 партий:

```
node quoridor-engine/arena/src/cli.js match \
  --adapter quoridor-engine/arena/adapters/quoridor.js \
  --bots quoridor-engine/arena/bots.json --a v1-hard --b v1-hard \
  --games 150 --threads 4
```

Ожидаемый результат: `+75 =0 -75`, score 50.0%, Elo 0.0, plies mean 71.5,
median 74, min 19, max 108, `loops: 0/150`, все партии завершаются победой.

Эталон уровней (roundrobin, 200 партий на пару): expert d5 — 37, hard d4 — −4,
medium d3 — −5, easy d2 — −28. Отдельно medium против easy, 1000 партий:
`+536 =0 -464`, Elo 25.1 [3.5, 46.8], LOS 98.9%, петли 0/1000.

Признак поломанной игры, которого нельзя допустить: партия заканчивается за
~14 полуходов, **ни одной стены не поставлено**, обе пешки идут по одной
колонке, победитель определяется тем, кто на полшага раньше встал на целевую
линию. Наблюдалось на сайте со старым движком. Если видишь такое — движок не тот
или сломалась оценка/поиск.

## Что нужно сделать

1. Серверные пути (`src/bots/BotManager.js`, `src/bots/defaultBots.js`,
   `src/puzzles/puzzleGenerator.js`) переключить на `createEngineV1`. Нужен
   отдельный экземпляр движка на каждую игру; разобраться с очисткой по
   завершении игры, состояние не должно протекать между партиями.
2. Сгенерировать UMD-бандл v1 для браузера и отдавать его новым маршрутом.
3. Переключить `frontend/index.html` и `frontend/js/ai-worker.js` на этот бандл.
   Проверить, что браузерный путь отдаёт легальные ходы и что воркер создаёт свой
   экземпляр на игру.
4. Перенести антиповтор в v1 (см. выше).
5. Задать уровни 2/3/4/5 и отключить случайность.
6. Откатить или удалить правки в `src/core/ai-core.js` — они меняли старый
   движок вместо того, чтобы его заменить.
7. Обновить `quoridor-engine/tests/engine-parity.test.js`: он сверяет v0 с
   `src/core/ai-core.js` и после подмены движка сломается by design. Сделать
   осознанно и явно: либо перевести контракт на новое место, либо убрать проверку
   с явным комментарием, почему она больше не применима. Молча оставлять красный
   тест нельзя.
8. Обновить документацию, где описаны уровни сложности бота.

## Критерии готовности

- Все пути (сервер, браузер, воркер, генератор задач) используют один и тот же v1.
- Никакого дублирования логики правил; в браузере используется глобальный `Shared`
  из `/shared.js`.
- Ровно четыре уровня: 2/3/4/5, ни одного случайного хода.
- 0 петель на самопое, проверено на не менее 1000 партий на каждом уровне.
- Самопой на сайте ведёт себя как эталон арены: счёт сторон сбалансирован (около
  50/50), средняя длина партии в районе 60-90 полуходов, **не 14**.
- Ни один экземпляр движка не используется для двух партий или двух цветов.
- Все тесты проходят; падения нет.

## Чего делать нельзя

- Не трогать `quoridor-engine/engines/v0/index.js` — база для parity-тестов.
- Не дублировать правила: не создавать копию `quoridor-rules.js` под браузер.
- Не латать старый `src/core/ai-core.js` вместо подключения v1 — это уже
  пробовали, результат: 0 петель ценой полностью сломанной игры.
- Не добавлять сборщик/bundler.
- Не коммитить мусор в корне: `net.js`, `server.js`, `files/` — это локальные
  черновики, не часть проекта.

## Как проверять

- `npx jest --rootDir . quoridor-engine/tests/` — тесты движков и parity.
- Тесты сайта: посмотреть `scripts` в корневом `package.json` и запустить
  релевантные.
- Арена: команды `match` и `roundrobin` выше.
- Самопой с нулевыми петлями: написать отдельный скрипт, держать отдельный
  экземпляр движка на каждое кресло в каждой партии (`createEngineV1` на игру,
  **не** повторный `require` — он вернёт тот же объект). Обязательно проверять
  победу, а не только повторы: игра заканчивается, когда пешка достигает
  `GOAL_ROW` (`GOAL_ROW = [0, 8]`: P0 стартует на строке 8 и идёт к 0, P1 —
  наоборот). Без этой проверки все партии выглядят как зависшие на потолке
  полуходов, и результаты получаются бессмысленными. Петля считается как 3
  повтора одной позиции по полному ключу.

## Известный открытый вопрос

Прямой самопой v1 на глубинах 2 и 3 дал 0 петель и разумную длину (47 и 74
полухода), но счёт сторон вышел 150/0 вместо ожидаемого ~50/50, который даёт
арена на той же глубине. Расхождение не объяснено. Если оно воспроизведётся —
это баг; найти его до того, как считать задачу выполненной.
